# Task--time graph construction and a matched RL comparison

The first constructor uses a shared `16 → 48 → 1` MLP (865 parameters),
imitation initialization, then four-rollout grouped leave-one-out REINFORCE.
It has no critic. Its features cannot distinguish all profiles with different
time locations. Earlier task--time and MILP coefficient-graph experiments in
paper 2 are repair controllers, not this cold-start constructor.

## Implemented neural structure

`../rl_construct_graph.py` adds an 89,009-parameter heterogeneous graph encoder:

- Task nodes: priority, power, startup/run/period/window parameters, remaining
  status and current execution. There are no task-index embeddings.
- Time nodes: solar, current load, residual instantaneous capacity, charge,
  normalized time, remaining eligible-task count, approximate mandatory-load
  density and cumulative net energy.
- Bipartite edges: task-window eligibility, with current execution, task power
  and residual capacity if the task occupies the slot as edge features.
- Temporal encoder: a bidirectional width-48 GRU over ordered time nodes, using
  the full offline profile available to every comparator. This is an ordered
  temporal representation, not a battery-feasibility certificate.
- Two alternating attention-message-passing rounds, time-to-task then
  task-to-time, with edge biases/values, residuals and layer normalization.
- Candidate decoder: concatenate the candidate's 16 features, selected task
  embedding, embeddings pooled over the actual proposed execution slots,
  remaining-task context and time context; score and softmax over valid choices.

This is an attention GNN on a task--time bipartite graph, combined with a temporal
GRU. It does not use the MILP variable--constraint graph or a task-ID lookup.
Task permutation equivariance is tested. Time order is intentionally meaningful.
The encoder operates on the current partial schedule at every decision.

RL still selects a complete task profile generated by the same DP backend.
It does not generate arbitrary schedules or continuous energy prices. The graph
changes the observation/decision representation; it does not enlarge the action
menu, enforce completion feasibility, add backtracking, or provide optimality.

## Literature basis and limits

[MIStar, NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/77629f2df5ef97ad967157c69cd8af7b-Abstract-Conference.html)
uses a heterogeneous graph, memory and parallel improvement search for FJSP.
Its reported gains apply to its own task and protocol. A cold-start ONTS
constructor must first handle different battery and recurrence constraints.

[ReSched, ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/467e109270678b3e2b3c2e7fa6b3d575-Abstract-Conference.html)
uses simplified FJSP states and modified Transformer attention. It shows that
graph complexity is not itself a requirement for strong scheduling performance.
Its four-feature state is not assumed sufficient for ONTS.

[POMO, NeurIPS 2020](https://arxiv.org/abs/2010.16011)
motivates comparing multiple solutions of a common instance and exploiting
solution symmetries. Our grouped leave-one-out baseline uses independent
rollouts without POMO's forced distinct starts; it is not a reproduction.

The implemented model is a literature-informed ONTS adaptation. Calling it
state of the art requires matched external benchmark evidence, not merely a
graph encoder or a newer optimizer.

## Frozen controlled study

`results/rl-construct-graph-20261011-fresh` freezes source, settings and data
before training. The first attempted seed range was rejected before training
because the strengthened overlap check detected prior instance hashes. The
fresh run uses a distinct seed range and checks both previous manifests and
protocol manifests, including the preceding construction pilot.

Twelve training instances, twelve untouched same-size and six larger instances;
three policy seeds (11, 29, 47); 64 RL updates with four rollouts each. Larger
sizes never appear in training. The two architectures share exactly the same
training teacher trajectories, candidate menu, rewards, instance selection,
rollout seeds and wall-clock inference allowance (2 seconds). Each architecture
has frozen warm imitation, replay continuation, and RL continuation arms.
Uniform and priority construction supply architecture-independent controls.
Eight methods, eighteen instances and three seeds yield 432 evaluations.

Twenty teacher epochs use minibatches of eight decisions, Adam at 0.001.
Both continuation arms reset Adam at 0.001; each replay update sees eight fixed
teacher decisions and matches one RL update. This protocol differs from the
preceding pilot, so cross-study score differences are not architectural effects.
Within this study, architecture comparisons are matched. Replay and RL match
optimizer-step counts, not transition counts or training runtime. No critic,
PPO clipping, auxiliary completion predictor or test-time tuning is introduced.

The declared primary contrast is graph RL minus graph replay on on-time terminal
utility: `1 + objective / (T * sum(priority))` for a successful construction,
zero for failure. Feasibility rates remain separately visible. This scalar
balances feasibility probability and feasible quality; it is not exactly
lexicographic. RL's training failures have a small partial-completion reward;
evaluation utility intentionally gives failures zero.

Policy-seed means are averaged within each instance; 4,000 instance-bootstrap
resamples supply exploratory marginal intervals. Same-size/larger contrasts and
graph-versus-MLP contrasts are secondary. All results, including negative ones,
are retained. A favorable pilot interval would still require untouched external
distributions and additional independent training seeds for confirmation.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 ONTS_SOLVER_THREADS=1 \
  .venv/bin/python -m projects.scheduling.research.rl_construct_study \
  --output projects/scheduling/research/results/rl-construct-graph-20261011-fresh \
  --architectures mlp graph --episodes 64 --policy-seeds 11 29 47 \
  --data-seed 2026101100 --train-per-regime 4 --test-per-regime 4 \
  --ood-per-regime 2 --budget 2 --reference-budget 5
```

Audit using `research.audit_rl_construct` and the same output path. Source
snapshots, protocol, instance JSONs, teacher states, trajectories, checkpoints,
reference schedules, evaluation schedules and paired contrasts are saved.

If the graph helps both imitation and RL equally, that is a representation gain.
If graph RL beats graph replay on untouched cases, that is evidence for an RL
continuation gain under this protocol. If failures persist, the next mechanism
to test is completion-aware lookahead or learned backtracking under the same
backend for every comparator. Neither result should be assumed in advance.

## Completed result

The graph model does not improve this recipe. Same-size/larger success counts:

| Method | Same-size | Larger |
|---|---:|---:|
| Uniform | 36/36 | 18/18 |
| MLP imitation | 34/36 | 17/18 |
| MLP replay | 34/36 | 15/18 |
| MLP RL | 34/36 | 18/18 |
| Graph imitation | 34/36 | 17/18 |
| Graph replay | 33/36 | 16/18 |
| Graph RL | 34/36 | 11/18 |

Primary pooled graph-RL-minus-replay utility: -0.073832, marginal interval
[-0.212721, 0.042145]. The larger-only contrast is -0.313376 with interval
[-0.582219, -0.052077]. No graph RL advantage is established.

MLP RL minus replay has a favorable larger-only contrast, 0.191130 with interval
[0.000491, 0.437853], but the pooled interval [-0.025373, 0.152935] includes zero
and the same-size interval [-0.050646, -0.006443] favors replay. This is tentative
secondary evidence rather than a general or confirmatory RL advantage. Uniform
already achieves 100% feasibility here, limiting the benchmark's usefulness for
demonstrating a feasibility improvement.

All 18 reference solves time out; there are no certified optimum gaps. No
evaluation overruns. Independent frozen-source replay validates 2016 schedules,
18 reference schedules and 18 checkpoints. Forty-four relevant tests passed
before a concurrent profile-backend change. The frozen source snapshot avoids
that unrelated dependency change when replaying this experiment.

Replay against the hash-verified frozen snapshot from the foreblocks root:

```bash
.venv/bin/python projects/scheduling/research/audit_rl_construct_frozen.py \
  --output projects/scheduling/research/results/rl-construct-graph-20261011-fresh
```

Graph dead ends occur in 0.071--0.160 seconds, leaving most of the two-second
allowance unused. The next intervention should explicitly test recovery
(restarts/backtracking) and completion-aware profile proposals with matched
controls. Increasing network size does not address the restricted action menu.
The MLP remains the default; retain the graph as a documented negative result.
